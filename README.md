# Windows 实时字幕与翻译工具

> 状态：实施中（T00 上游基线已导入；T01 已确认本机原生构建，用户确认手动启动；安装包、浮层、退出和音频/翻译尚未验证）
>
> 代码基础：[`fmadore/Live-translation`](https://github.com/fmadore/Live-translation)，MIT License
>
> 目标设备：Windows 10 x64；当前审计机器为 Windows 10 Pro 22H2 19045.2965（2026-10-21 核验），后续兼容 Windows 11
>
> 产品方向：采集电脑正在播放的声音，在本机实时识别并显示字幕；尽可能离线，可选翻译，不合成或回传用户语音。

## 项目目标

基于 Live-translation 的 Tauri、Rust、Whisper 和字幕浮层能力，做一个供个人使用的跨应用实时字幕工具。适用场景包括游戏、语音聊天、视频、浏览器内容和 Teams 等会议软件，只要声音经由 Windows 播放设备输出即可。

第一阶段面向当前 Windows 10 19045：采用 WASAPI 设备回环采集当前播放设备的混合声音。Windows 10 19045 不支持项目所需的按进程捕获接口，因此首版不承诺只采集某一个应用；用户可选择播放设备，其他经过同一设备输出的声音也可能进入识别流程。Windows 11 的按应用采集作为后续可选能力，不作为 Win10 首版的前置条件。

## 产品边界

- 只生成字幕和译文，不把用户语音转换、配音或发送给会议中的其他人。
- 不加入会议、不读 Teams 私有接口、不绕过权限或组织策略。
- 仅在用户按下开始后采集；显著显示当前状态，并提供暂停、继续、停止和退出即停止。
- 默认只在内存中短暂缓冲用于实时识别的音频，不保存录音，也不自动保存字幕。
- 用户可主动导出 TXT/SRT/VTT 并清除本次字幕；日志不记录完整字幕、音频或会议身份信息。
- 本地处理不等于免于遵循会议规则。真实会议使用前，用户应确认组织要求和参与者知情要求。
- “任何场景”限于电脑音频输出可被 Windows 回环接口采集的场景；受保护、独占模式或特殊音频路径可能不可用，需显示原因，不静默改用麦克风。

## 第一版范围（MVP）

1. 在上游代码基础上建立可追踪、可回滚的个人开发分支，保留 MIT 许可、版权声明和上游来源。
2. 让应用在 Windows 10 x64 / build 19045 启动；将 Windows 11 的单应用采集依赖隔离为可选能力。
3. 实现播放设备枚举、选择和系统混合声音 WASAPI 回环采集；采集开始、暂停、继续、停止及设备断开状态明确。
4. 复用上游本机 Whisper 字幕流程，支持语言选择/自动识别、临时字幕和定稿字幕。
5. 评估并接入至少一种可在本机运行的文本翻译模型，默认目标语言为简体中文；首发只承诺经验证的语言组合。若模型在用户电脑上无法满足实时性，保留原文字幕并把翻译模型标为可选，不静默调用云服务。
6. 保留上游字幕浮层，支持置顶、拖动、字体大小、透明度和复制字幕；界面标示当前播放设备及“采集整个设备混音”的范围。
7. 默认不保存；用户主动选择后可导出文本/SRT/VTT，且能清空字幕。
8. Windows 11 的按应用进程采集列为后续能力；Win10 不支持时明确说明，绝不伪装成只捕获单一应用。

## 暂不纳入

- 语音变声、语音合成、虚拟麦克风和向游戏/会议发送译文。
- 自动录音、自动保存历史、云端识别、云端翻译或账号同步。
- 多人说话人分离、会议摘要、会议纪要和自动行动项。
- 对所有语言、所有游戏反作弊环境及所有音频驱动作兼容保证。

## 技术方向与关键决策

- **上游基线：**基于 `fmadore/Live-translation` 的固定 tag/commit 开发；为本项目建立独立 GitHub fork/仓库，记录 `upstream`，不直接改写上游默认分支。
- **桌面与字幕层：**沿用 Tauri 2、Rust、TypeScript/Svelte 界面和上游浮层；先验证上游构建及打包是否可在 Win10 运行，再决定具体改动。
- **音频：**首版采用共享模式 WASAPI render loopback（系统播放设备混音），统一成识别引擎需要的采样格式；设备级回环和按进程回环必须作为不同模式呈现。
- **按应用采集：**微软的进程回环 API 最低要求为 Windows 10 Build 20348；当前设备 build 19045 低于该要求。故 Win10 使用系统设备混音；Win11 可单独实现并测试按进程采集。
- **语音识别：**优先复用上游本地 Whisper 引擎及模型管理，启动模型下载前展示大小和目标位置；禁止运行期未经提示调用远程识别 API。
- **本机翻译：**先比较上游可用能力与候选模型的许可证、语言组合、内存/显存占用、包体和延迟，再选型。模型可在联网时下载，下载并验证后支持断网运行。
- **质量策略：**优先可理解、可跟读和低延迟；呈现原文与译文、保留原文以便核对；同一条临时字幕允许更新，定稿后不重复跳动。

## 阶段与决策门

### 阶段 A：上游审计与 Win10 构建门

- 固定上游 tag/commit，阅读许可证、音频入口、Windows 最低版本、安装配置和模型下载流程。
- 在目标 Windows 10 上验证上游干净构建与启动；若失败，先判断问题来自包格式、Windows API、运行库还是依赖，不先重写 UI。
- 产出上游差异清单与最小改造方案；任何超出 MIT 许可或涉及第三方模型再分发的事项先核对条款。

### 阶段 B：Windows 10 系统音频

- 在不保存音频的前提下枚举播放设备并采集所选设备混音。
- 验证开始/暂停/停止、静音、设备切换、无声音、程序退出与资源释放。
- 界面明确说明所有经过所选设备的应用声音都可能被采集；确认不支持的独占/受保护音频如何提示。

### 阶段 C：本机字幕与翻译

- 先接通上游本机 Whisper 原文字幕，确定目标机器资源基线和可接受延迟。
- 单独评估本机翻译模型；锁定模型、语言范围与许可证后，再接入译文管线。
- 若暂时无法保证可用的本地译文，交付原文实时字幕与可选实验翻译，不暗中切换云端。

### 阶段 D：通用字幕体验与数据控制

- 完成浮层、语言、字体、位置、复制和字幕导出。
- 设置不保留会话历史为默认；退出清除内存音频缓冲；用户主动导出的字幕由用户管理。
- 加上设备状态、推理延迟、过载、模型未安装和翻译失败提示。

### 阶段 E：Win11 可选采集与发布

- 在支持的 Windows 11 系统添加按应用进程采集，并与系统设备混音模式并列显示。
- 对 Win10 19045、Win11、独占/受保护音频、设备热插拔进行验收。
- 检查依赖与模型许可、隐私说明、安装包签名/来源和发布内容后，再发布个人 fork 的版本。

## 首版验收标准

- 应用能在 Windows 10 build 19045 启动；系统要求与限制清楚显示。
- 用户选择播放设备并显式开始后，可看到当前设备混音的活动状态和连续原文字幕。
- 本机翻译只在通过延迟/语言验证后作为首发承诺；失败时原文仍正常显示。
- 默认断网运行（首次模型获取之后）；网络请求仅限用户触发的模型获取、更新或明确开启的云服务。
- 应用不产生录音文件，不自动保存字幕；停止后停止采集并释放设备。
- 至少验证游戏、语音聊天、浏览器视频和 Teams 四类播放音频；测试使用受控内容，不保存真实会议音频。
- 进程级捕获在 Win10 19045 不可选；界面不会把整机混音误报为单一应用捕获。

## 主要风险

- 当前设备 build 19045 不支持按进程回环；系统混音会包括同一输出设备上的通知、游戏声和其他应用声音。
- 原项目声明 Windows 11；本机 Win10 19045 已确认构建产物，用户确认手动启动，但安装包、浮层、退出和音频功能尚未验证。构建能启动不代表所有音频功能都可用。
- Whisper 本身的本地“翻译”主要适用于翻译成英语；中文及其他目标语言需单独选本机文本翻译模型。
- 小模型速度快但准确率可能下降；较大模型需要更多内存、显存和存储。用户设备硬件尚未完整盘点。
- 游戏音效、多人同时说话、口音和专有名词会影响识别质量；字幕是辅助理解，不是可靠记录。
- 上游更新可能改变接口；通过固定上游版本、清晰分支和逐任务提交降低合并/回滚成本。

## 当前计划默认值

- 操作系统：Windows 10 x64 build 19045 为首要验证目标。
- 音源：系统播放设备混音；麦克风采集默认关闭。
- 识别：本机 Whisper，模型首次下载后可离线。
- 翻译：优先简体中文本机翻译；未通过评估前不承诺实时质量，也不调用云服务。
- 保留：不保存音频，不自动保存字幕；用户手动导出才写入文件。
- 语音输出：不变声、不合成、不回传。
